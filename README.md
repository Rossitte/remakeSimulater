# 《投胎模拟器》 remakesimulator.online

你现在是一名资深前端工程师、游戏系统设计师和数据架构师。

我要开发一个轻量级网页小游戏：

# 《投胎模拟器》

***

# 一、游戏核心理念

这不是传统的人生模拟经营游戏。

玩家不需要经营人生，也不需要每年做选择。

游戏的核心体验只有一句话：

> **“如果我重新投胎一次，我会拥有怎样的一生？”**

玩家只需要：

```
点击「开始投胎」
        ↓
随机获得出生信息
        ↓
系统在后台自动模拟这一生
        ↓
直接生成完整人生结果
        ↓
给出人生评价
        ↓
保存本次人生
        ↓
点击「再次投胎」

```

玩家的核心体验应该是：

> **投胎 = 抽卡**
>
> **人生 = 开奖结果**

每次投胎都应该具有随机性、未知感和期待感。

***

# 二、最重要的设计原则

## 1. 极简

不要把游戏做成复杂的人生模拟器。

不要加入：

- 每年操作
- 每月操作
- 玩家选择职业
- 玩家经营属性
- 复杂技能树
- 复杂装备
- 卡牌战斗
- 复杂任务系统
- 复杂经济系统
- 大量菜单
- 大量弹窗

玩家不需要控制人生。

***

## 2. 玩家只负责“投胎”

玩家只需要点击：

> 【开始投胎】

然后观看结果。

***

## 3. 大量复杂逻辑隐藏在后台

游戏内部可以拥有复杂的人物属性、职业、财富、健康、家庭、事件等模拟逻辑。

但是这些内容：

> **默认全部隐藏。**

玩家只看到最终结果。

例如后台可以生成：

```
intelligence
health
appearance
luck
wealth
education
social
personality
family
career
marriage
children
majorEvents
deathCause

```

但玩家不需要看到这些原始数值。

这些数据只是为了让最终人生结果更加合理和丰富。

# 五、投胎系统

投胎系统是整个游戏最核心的系统。

## 出生国家

不能简单使用：

```
Math.random()

```

直接随机国家。

必须使用：

> **加权随机。**

国家权重应该综合：

- 世界人口
- 出生率
- 人口结构
- 国家出生人口规模
- 城市化程度

最终得到一个相对合理的出生概率。

不要追求数学意义上的绝对精确。

目标是：

> **让玩家感觉自己真的在按照现实世界的出生概率随机投胎。**

***

# 六、国家数据

建立独立的数据文件。

例如：

```
src/data/countries.ts

```

国家至少包含：

```
{
  id: string,
  name: string,
  nameEn: string,

  population: number,
  birthRate: number,

  economicLevel: number,
  educationLevel: number,
  healthcareLevel: number,
  safetyLevel: number,

  lifeExpectancy: number,

  cities: string[]
}

```

第一版准备足够多的国家，建议至少：

> 30～50 个国家。

但是数据结构必须允许未来轻松扩展到更多国家。

不要把国家数据写死在 React Component 中。

***

# 七、城市系统

确定国家之后，再随机确定城市。

城市也必须使用加权随机。

城市权重综合：

- 城市人口
- 城市出生人口
- 城市规模
- 城市化程度

城市应该分成：

- 超大型城市
- 大城市
- 中型城市
- 小城市

不能让玩家几乎每次都出生在首都。

例如：

```
中国
 ↓
上海

```

应该和：

```
中国
 ↓
成都

```

以及：

```
中国
 ↓
某个普通中小城市

```

同时存在。

# 十六、人生评价文字

必须根据本次人生真正发生的事情动态生成。

不要简单随机一句评价。

例如：

### 高财富 + 高家庭 + 高健康

> “你没有经历太多惊天动地的故事，但拥有稳定的事业、幸福的家庭和相当充裕的财富。对大多数人来说，这已经是一场非常成功的人生。”

### 高事业 + 低家庭

> “你把大部分时间都交给了事业。你成功了，但当你回头看的时候，才发现自己错过了很多原本可以拥有的东西。”

### 低财富 + 高幸福

> “你没有赚到很多钱，却拥有几个真正爱你的人。你的一生并不富裕，但你很少觉得自己是一个失败者。”

### 极端幸运

> “如果人生是一场抽卡，你这一把的运气已经接近作弊。”

### 极端悲惨

> “你的出生并不幸运，而命运似乎也没有打算给你太多机会。”

评价必须根据人生数据动态组合。

# 二十五、开发纪律

每次开始一个 Phase 时：

1. 先阅读当前项目代码
2. 理解当前架构
3. 不要破坏已经完成的功能
4. 修改前先规划
5. 完成后检查 TypeScript 错误
6. 检查运行时错误
7. 检查核心逻辑
8. 不要生成无意义的占位代码
9. 不要擅自增加新的复杂系统

如果某个功能没有明确要求：

> **优先保持简单，而不是主动扩展。**

如果认为某个地方需要扩展：

先说明原因，再等待确认。
